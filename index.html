EL PROBLEMA

Hay potencia de cómputo de sobra. Está apagada en salones y despachos.

El coste de las GPUs y la memoria de alto rendimiento no deja de subir, empujado por la demanda de la IA. Para muchos, la única vía de acceso a cómputo intensivo es asumir costosos alquileres por hora en grandes plataformas centralizadas. Mientras tanto, millones de procesadores y tarjetas gráficas en todo el mundo pasan la mayor parte del día en reposo.

5 GHz+

¿Tienes un procesador potente pero necesitas el músculo de una tarjeta gráfica de alta gama para entrenar un modelo de IA o renderizar en 3D? Con Synergia dejas de pagar facturas abusivas en la nube. Prestas tu CPU inactiva para validar tareas de otros, acumulas créditos de forma gratuita y los canjeas para lanzar tus cálculos masivos sobre las GPUs de la red. Tu hardware doméstico financia tu acceso a supercomputación especializada: sin intermediarios, sin comisiones y sin comprar hardware nuevo.

FUNCIONAMIENTO

Flujo de Trabajo de Cómputo Distribuido

Del repositorio a los resultados procesados en paralelo, de forma 100% aislada mediante contenedores y verificada mediante consenso.

01
repo/config.toml

Definición del contrato

El programador define un fichero de configuración estándar en la raíz de su repositorio. Synergia utiliza este fichero para compilar, instalar dependencias, ejecutar el procesamiento por rango y limpiar las salidas.

Makefileconfig.toml
# --- Contrato de Tarea Synergia ---setup:	@mkdir -p inputs outputsrun:	python3 calculate.py $(START) $(END)clean:	rm -f outputs/*.json

INICIO RÁPIDO

Empieza a Contribuir en 3 Pasos

No necesitas configuraciones tediosas ni infraestructuras complejas. Instala el cliente oficial, apunta de forma obligatoria al servidor de tu elección, autentícate y empieza a procesar tareas en segundos.

01

Instala el Cliente CLI

Descarga e instala la herramienta interactiva del cliente en tu sistema de forma global directamente desde PyPI.

Terminal
pip install synergia
02

Configura el Servidor

Al tratarse de una arquitectura federada y descentralizada, se deben configurar los endpoints de conexión correspondientes. Cada servidor orquesta su propio clúster de tareas, colas de mensajería y ledger de créditos independiente; según los servidores configurados, el nodo se integra en una red de cómputo de Synergia u otra, existiendo plena flexibilidad para unirse a redes públicas, privadas o desplegar infraestructura propia.

~/.config/synergia/config.ini
cat > ~/.config/synergia/config.ini <<'EOF'
[rest]
base_url = https://{rest-endpoint}
base_port = 443

[ws]
base_url = wss://{websocket-endpoint}
base_port = 443
EOF
Ver guía para desplegar tu propio servidor Synergia
03

Autenticación y Ejecución

Tras iniciar sesión de forma segura a través del proveedor preferido (como GitHub, Google o credenciales locales), se puede comenzar a procesar tareas directamente con comandos de ejecución o mediante la activación del planificador automatizado (p. ej., utilizando synergia subscribe-task --task-id <id> o synergia start-scheduler).

Terminal
# Autenticación / Login
synergia login-github

# Iniciar planificador automático / Run automated scheduler
synergia start-scheduler --mode round-robin
Ver todos los métodos de autenticación (Google, GitHub, email) y comandos CLI

SEGURIDAD INTEGRAL

Aislamiento Estricto y Auditoría Automática

Ejecutar código ajeno en tu hardware requiere garantías totales. Synergia combina aislamiento a nivel de sistema operativo y red, con un proceso de consenso criptográfico robusto.

Sandboxing con Docker

Cada proceso corre dentro de un contenedor Docker efímero y ligero, con namespaces de Linux, hilos limitados (cgroups) y sin privilegios de root.

Bloqueo de Red por Firewall

Aislamiento de red mediante iptables. Se bloquean todas las conexiones entrantes y salientes para asegurar que la tarea no pueda exfiltrar datos ni realizar peticiones sospechosas.

Auditoría Estática del Repositorio

Antes de que el nodo worker acepte y ejecute una tarea, el sistema analiza el repositorio para verificar que el Makefile y scripts no contengan llamadas maliciosas.

Verificación SHA-256 Cruzada

Consenso: al menos dos nodos deben devolver el mismo hash SHA-256 de los ficheros de salida del procesamiento para dar por válido un bloque.
