# Synergia

> Plataforma de cómputo distribuido voluntario con verificación de resultados y sistema de incentivos por créditos.

Synergia es un ecosistema de código abierto diseñado para convertir ciclos de CPU/GPU inactivos de ordenadores personales y servidores en una economía de créditos de cómputo. Permite publicar y ejecutar tareas pesadas (como renderizado 3D, entrenamiento de modelos de IA, análisis científico o criptografía) de forma aislada, determinista y segura, eliminando la dependencia exclusiva de proveedores de nube tradicionales (AWS, GCP, Azure).

## Arquitectura de Synergia

El proyecto está dividido en dos componentes de software principales y autónomos:

### 1. Servidor (`synergia-server`)
- **Descripción:** Actúa como el orquestador y la API central del sistema. Gestiona la autenticación, la cola global de tareas, las ofertas de cómputo, los balances de créditos de los usuarios y la monitorización en tiempo real.
- **Tecnologías:** Node.js, Express, PostgreSQL, WebSockets, Docker, Prisma, Grafana, Prometheus.
- **Rutas de la API (REST):** Documentada detalladamente en [API Reference](https://yagomilenio.github.io/synergia-docs/docs/api-rest/).
- **API WebSocket:** Intercambio de mensajes bidireccional en tiempo real para workers y clientes. Documentación detallada en [WebSocket Reference](https://yagomilenio.github.io/synergia-docs/docs/api-websocket/).

### 2. Cliente y Worker (`synergia-client`)
- **Descripción:** Una interfaz de línea de comandos (CLI) que cumple un doble rol según los argumentos que reciba:
  - **Cliente (Publicador):** Permite a los usuarios empaquetar tareas, publicarlas en la red ofreciendo una recompensa en créditos, y recuperar los resultados verificados.
  - **Worker (Proveedor de cómputo):** Se ejecuta en segundo plano en las máquinas voluntarias, conectándose al servidor mediante WebSockets para reclamar tareas, ejecutarlas de forma segura y devolver los resultados.
- **Tecnologías:** Go (Golang), Docker Engine API (para la ejecución y aislamiento), WebSockets.

## Flujo de Trabajo de las Tareas (Task Lifecycle)

El ciclo de vida de una tarea en Synergia consta de las siguientes fases:

1. **Definición y Publicación:** El usuario define la tarea en un archivo `task.toml` donde especifica la imagen Docker base, el comando de entrada, los archivos necesarios, los recursos máximos y la recompensa en créditos. El CLI del cliente empaqueta los archivos de entrada (`input.tar.gz`) y los sube al servidor.
2. **Asignación:** Un worker libre con las capacidades técnicas requeridas reclama la tarea a través de una conexión WebSocket.
3. **Ejecución Aislada:** El worker descarga los datos, descarga la imagen Docker requerida y ejecuta el contenedor en un entorno sandbox estrictamente aislado (sin red y con límites estrictos de CPU/Memoria).
4. **Verificación de Resultados:**
   - **Tareas Deterministas:** Synergia soporta la replicación redundante de tareas para verificar el hash SHA-256 de los resultados. Si múltiples workers obtienen el mismo hash exacto, se da por válida.
   - **Tareas No Deterministas (p. ej., entrenamiento de IA con varianza):** El publicador define algoritmos de validación específicos o validación local asistida.
5. **Transacción de Créditos:** Si el resultado es válido, el servidor transfiere los créditos del balance del publicador al balance del worker (o workers) que ejecutaron la tarea correctamente.

## Seguridad y Aislamiento (Sandboxing)

La seguridad es el pilar fundamental de Synergia, ya que los workers voluntarios ejecutan código arbitrario subido por terceros.
- **Aislamiento de Contenedores:** Las tareas se ejecutan exclusivamente dentro de contenedores Docker con perfiles de seguridad reforzados.
- **Desactivación de Red (`--network none`):** Ninguna tarea en ejecución tiene acceso a internet ni a la red local del host para evitar exfiltración de datos, ataques de denegación de servicio o propagación de malware.
- **Límites de Recursos:** Se restringe estrictamente la memoria RAM máxima y el número de núcleos de CPU para evitar que una tarea maliciosa o mal programada cuelgue o degrade el sistema anfitrión.
- **Límites de Almacenamiento:** El espacio en disco de escritura de la tarea está acotado.
- **Tokens de Autenticación de Corta Duración:** Los workers y clientes se autentican mediante JWT seguros, renovados periódicamente.

## Modelo Económico y Sistema de Créditos

Synergia utiliza un modelo de créditos virtuales diseñado para incentivar el comportamiento honesto de la red sin la sobrecarga de una blockchain.
- **Incentivos:** Los usuarios ganan créditos aportando cómputo inactivo (actuando como workers). Consumen créditos publicando sus propias tareas.
- **Reputación:** Cada worker posee una puntuación de reputación dinámica basada en su tasa de éxito en las verificaciones. Una reputación alta otorga acceso prioritario a tareas con recompensas elevadas, mientras que comportamientos maliciosos o fallos constantes conllevan penalizaciones y exclusión de la red.
- **Sin Blockchain:** La orquestación y el balance de créditos se centralizan a través del servidor para optimizar la latencia y eliminar comisiones por gas o minería ineficiente.

## Estructura de Configuración de Tareas (`task.toml`)

Ejemplo de definición de tarea determinista:

```toml
[task]
name = "Renderizado de Frame de Licuadora"
image = "lenders/blender:latest"
timeout = 300 # segundos
recompensa = 15.0 # créditos
deterministic = true

[resources]
cpus = 4
memory = "4096MB"

[files]
input = "escena_3d.blend"
output = "render_output.png"
```
